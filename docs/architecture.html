Two independent processes: a Vite dev server on port 3000 serving the Vue SPA, and a Uvicorn/FastAPI process on port 8001 serving JSON. They share no code and communicate only over HTTP. There is no database, no authentication, and no build-time coupling — the client hardcodes the API origin.

Request data flow

A representative round trip — the user changes a filter on the Dashboard.

FilterBar.vue
User picks a warehouse. The bound ref lives in the composable, not the component.
composables/useFilters.js
Four refs (selectedPeriod, selectedLocation, selectedCategory, selectedStatus) are declared at module scope — a singleton, so every view shares one filter state without prop drilling.
views/Dashboard.vue
A watcher on the filter refs re-runs the loader. getCurrentFilters() maps UI names to API names — selectedLocation becomes warehouse, selectedPeriod becomes month.
api.js
Builds a URLSearchParams, dropping any filter whose value is 'all' so the param is simply absent. Issues the axios GET.
main.py · route handler
FastAPI coerces query params into Optional[str] arguments.
main.py · apply_filters()
Sequential list comprehensions over the in-memory list. Category and status compare lowercased; warehouse compares exactly. Each pass rebinds a new list, so the source data is never mutated.
main.py · filter_by_month()
Accepts either 2025-03 or Q1-2025. Quarters expand through QUARTER_MAP into three month prefixes, then match by substring against order_date.
main.py · aggregation
For the dashboard: inventory value, low-stock count, pending orders, and total order value are computed from the already-filtered lists.
Pydantic response_model
Validates and serializes on the way out. A field present in JSON but missing from the model is silently dropped — which is why model updates must follow data changes.
Vue reactivity
The response lands in a ref; every derived figure and chart series is a computed off that ref, so the DOM updates without imperative redraw code.

Observations

Things worth knowing before you change anything — found by comparing the client's API calls against the routes the server actually registers.

Six client API methods target routes that do not exist

api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder, and getPurchaseOrderByBacklogItem, hitting /api/tasks and /api/purchase-orders. Neither path is registered in main.py, and both would need non-GET verbs. Every call 404s.

client/src/api.js:77–105 · server/main.py

The task failures are swallowed, so the UI looks fine

App.vue calls loadTasks() on mount, catches the 404, and logs to console. The task list then renders only the hardcoded entries from useAuth, merged with an apiTasks array that stays empty. Adding a task appears to fail silently from the user's side.

client/src/App.vue:89–105

has_purchase_order is always false

/api/backlog flags each item by scanning purchase_orders, but purchase_orders.json is an empty array and no endpoint can write to it. The flag is dead until a POST route exists.

server/main.py:169–180 · server/data/purchase_orders.json

Reports.vue bypasses the API client

It imports axios directly and hardcodes http://localhost:8001 twice, rather than going through api.js. The two reports endpoints are the only ones with no wrapper method.

client/src/views/Reports.vue:128, 156, 162

The API origin is hardcoded in two places

API_BASE_URL in api.js and the literals in Reports.vue. There is no environment config, so the frontend only works against a local backend.

client/src/api.js:3

Test coverage is backend-only

40 pytest tests cover inventory, dashboard, and misc endpoints via TestClient. There are no frontend tests — no test runner is installed in client/package.json.
